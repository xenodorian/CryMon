2. HARD RULES FOR ART
======================================================================
  - ONE art tree: public/sprites/. Tools that write PNGs must go
    through tools/sprite_root.assert_write(), which refuses any other
    path. Never create another folder named "sprites".
  - Never reuse another character's sprite for a named character.
  - Missing art stays tagged PLACEHOLDER_ART. Current placeholders carry
    a magenta (255,0,255) "PH" or "PLACEHOLDER" tag. That is how to find
    them.
  - Do not touch Max's walk cycle (public/sprites/max/) unless the user
    names Max.
  - Do not replace art the user supplied (for example Lead's files, see
    section 4) without the user saying so.
  - Show every generated image to the user and get approval before
    committing it. Generated results vary; the user decides.

======================================================================
3. ART SPECS (match these exactly)
======================================================================
All PNG, RGBA, transparent background. Pixel-art look (hard edges, no
blur, limited palette). Look at existing finished art for style, for
example public/sprites/monsters/quillpup/ and public/sprites/npc/bram-*.

  Monsters (battle): public/sprites/monsters/<id>/1.png .. 4.png
    - 4 idle frames (a small bob or breathing loop).
    - Finished art is roughly 96x128 to 128x128 (quillpup is 112x101).
      Keep 128x128 or smaller. Facing: check a finished monster.
  Overworld NPCs: public/sprites/npc/<id>-1.png .. -4.png
    - 48x64, 4 idle frames, feet at the bottom edge.
  Dialogue portraits: public/sprites/portraits/<id>.png
    - 160x200 bust.
  Species info (name, crystal type, blurb) is in content/species.json.
  The crystal type sets the color theme (docs/CRYMON.md "Crystal
  Natures": e.g. Obsidian = ghost/dark, Citrine = lightning).

Suggested process per asset:
  1. Generate one large image (e.g. 512 or 1024 px) from a prompt that
     names: pixel art, game sprite, full body, plain background, the
     creature or character description, and the color theme.
  2. Remove the background to transparency, crop to the subject.
  3. Downscale with NEAREST to the target size.
  4. Make the 4 frames from the one image (a 0/-1/-2/-1 px vertical
     bob, as tools/make_placeholder_npcs.py does), unless the model can
     give you consistent frames.
  5. Write with assert_write to the exact path above, overwriting the
     placeholder (the placeholder tools refuse to overwrite; your
     writer should overwrite on purpose).

Hugging Face call (VERIFY against current HF docs before relying on it;
endpoints and model names change):
  POST https://router.huggingface.co/hf-inference/models/<model-id>
  Header: Authorization: Bearer $HF_TOKEN
  JSON body: {"inputs": "<prompt>"}
  Response: image bytes on success.
  Pick a text-to-image model the account can use. Test one image first.

Put any generator script under tools/ (for example
tools/gen_ai_art.py). Never commit the token.

5. AFTER ART CHANGES: THE PIPELINE (run all, fix anything red)
======================================================================
  python3 ports/dreamcast/tools/gen_sprites.py     # PNG -> sprites.h
  python3 tools/bake_content.py --content content --out ports/dreamcast/src
  python3 tools/check_sync.py --strict            # must print OK
  make -C ports/dreamcast                          # needs the SH toolchain
  make -C ports/dreamcast cdi
  npm run -s typecheck && npm test && npx eslint .

Never hand-edit ports/dreamcast/src/content_*.inc or sprites.h; they
are generated. If the Dreamcast toolchain is missing in your session,
say so and still run the Python steps and web checks.

To eyeball the web build: npx vite dev --host 127.0.0.1 --port 8080,
then screenshot with Playwright (Chromium is at /opt/pw-browsers).
